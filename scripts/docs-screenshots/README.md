# Documentation screenshots

Every figure on ectlogger.us is generated by `capture.mjs` from a manifest. No
screenshot is ever taken by hand, and no screenshot is ever annotated in an
image editor afterward.

That is not fussiness. The six screenshots this pipeline replaced were taken by
hand in January, referenced from one place, and never touched again. By
September they showed a UI that had been redesigned twice, and nobody could
refresh them without repeating the original manual crop-and-annotate job from
memory. A figure you cannot regenerate is a figure that goes stale.

## Running it

All four steps run from the repository root. Use `backend/venv`, not the
repository-root `.venv` — the latter is a stale environment missing `pyotp`
and `pip`.

```bash
# 1. Build the demo database (fictional roster, no real operator data)
backend/venv/bin/python backend/scripts/seed_demo_data.py \
  --db backend/demo.db --out backend/demo-seed.json

# 2. Start the demo backend on port 8100. Port 8000 is beta's; leave it alone.
(cd backend && DATABASE_URL="sqlite:///./demo.db" \
  FRONTEND_URL="http://10.6.26.3:3100" \
  EMAIL_ENABLED=false SMTP_HOST=127.0.0.1 SMTP_USER=demo@example.com \
  SMTP_PASSWORD=demo SMTP_FROM_EMAIL=demo@example.com \
  SECRET_KEY=demo-only-not-a-real-secret APP_ENV=production \
  venv/bin/python -m uvicorn app.main:app --host 0.0.0.0 --port 8100)

# 3. Start the demo frontend on port 3100, pointed at that backend
(cd frontend && VITE_API_URL=http://10.6.26.3:8100/api \
  VITE_ALLOWED_HOSTS=10.6.26.3,localhost,127.0.0.1 \
  npx vite --host 0.0.0.0 --port 3100)

# 4. Capture
(cd scripts/docs-screenshots && npm install)   # first time only
node scripts/docs-screenshots/capture.mjs                     # everything
node scripts/docs-screenshots/capture.mjs --section operators  # one path
node scripts/docs-screenshots/capture.mjs --only speed-entry   # one figure
node scripts/docs-screenshots/capture.mjs --list               # dry run
```

Pass `DATABASE_URL` as `sqlite:///./demo.db`, **not** `sqlite+aiosqlite:///`.
`app/database.py` adds the `+aiosqlite` driver itself with a plain string
replace of `sqlite:///`, and that substring also matches inside
`aiosqlite:///`, so handing it the driver form produces
`sqlite+aiosqlite+aiosqlite:///` and a `too many values to unpack` failure out
of SQLAlchemy's dialect loader.

Output lands in `docs/img/<section>/<id>.png`, plus `docs/img/figures.json`
mapping every id to its path, alt text, and caption.

## The rules

**Never point this at beta or production.** Beta holds a copy of production's
database, real names and email addresses included. `capture.mjs` refuses to run
against either hostname, but the real safeguard is not doing it.

**Annotations are drawn at capture time from a selector.** A figure that tells
the reader where to click gets a bright red box around the target. Because the
target is a selector rather than pixel coordinates, it follows the control when
the layout changes instead of quietly pointing at empty space.

**No instruction may exist only inside an image** (WCAG 1.4.5). The prose names
the control by its label, and the `alt` text carries the same instruction in
words. A red box is invisible to a screen reader.

**Light mode only**, except the one figure that exists to show the dark theme.

**Selectors resolve to the first *visible* match, not the first match.** The app
mounts desktop and mobile copies of whole toolbars, and MUI parks hidden
measuring elements at -9999px, so the first match in document order is
routinely the one nobody can see. `capture.mjs` filters for visibility on both
`element` and `annotate`, and `inspect.mjs` reports the visible one, but a
selector that matches several visible things still takes the first. Make it
specific.

**A `label` on an annotation sits over the page**, so on a dense toolbar it will
cover the control next to the one you are pointing at. Use labels when a figure
carries several annotations and the prose has to refer to them individually.
For a single red box, let the caption do the work.

## Adding a figure

Put it in `requests/<section>.yml` rather than in `shots.yml`, so the people
writing a path are not all editing one file. Anything in `requests/*.yml` is
merged into the manifest automatically. Ids must be unique **within a section**;
two paths may each have their own `check-in-legend` because the output path is
`docs/img/<section>/<id>.png`.

```yaml
shots:
  - id: check-in-dialog
    section: operators          # also the output directory
    page: /docs/operators/checking-in/     # which page embeds it (documentation only)
    route: /nets/{{net:active}}            # appended to the demo instance URL
    as: KC1HILL                            # log in as this seeded callsign
    wait_for: 'table'                      # selector that means the page is ready
    steps:
      - click: 'button[aria-label="Check In"]'
      - wait_for: '.MuiDialog-root'
    element: '.MuiDialog-paper'            # capture just this, with padding
    pad: 16
    annotate:
      - selector: 'button[type="submit"]'
        style: box                         # box | underline
        label: 'Click here'                # optional red chip; omit for no label
    alt: >
      The check-in dialog, with the Check In button outlined in red at the
      bottom right of the form.
    caption: Only the callsign is required. Everything else is optional unless the net asks for it.
```

Then paste the figure into the page:

```html
<figure>
  <img src="/docs/img/operators/check-in-dialog.png"
       alt="The check-in dialog, with the Check In button outlined in red at the bottom right of the form.">
  <figcaption>Only the callsign is required. Everything else is optional unless the net asks for it.</figcaption>
</figure>
```

### Fields

| Field | Required | Meaning |
|---|---|---|
| `id` | yes | Filename, without extension. Unique across every manifest |
| `section` | yes | Output directory under `docs/img/` |
| `route` | yes | Path appended to the demo instance base URL |
| `alt` | yes | Real alt text. Describes what is shown, including any red annotation |
| `page` | no | The documentation page that embeds it. Documentation only |
| `as` | no | Seeded callsign to log in as. Omitted means signed out |
| `wait_for` | no | Selector to wait for before doing anything |
| `steps` | no | Ordered interactions: `click`, `hover`, `fill`, `press`, `wait_for`, `wait`, `scroll_to`, `evaluate` |
| `element` | no | Capture only this element, with `pad` pixels around it. A list of selectors captures their union |
| `pad` | no | Padding around `element`, default 12 |
| `with_online` | no | Callsigns to sign in and park on the same route first, so the app sees them as present |
| `full_page` | no | Capture the scrolled page. Rarely right: the app shell sets `overflow: hidden` on its root, which truncates a full-page capture to one screen. Use a tall `viewport` instead |
| `viewport` | no | `{width, height}`, default 1440x1000 |
| `mobile` | no | Touch and mobile emulation, for the field pages |
| `hide` | no | Selectors to make invisible, for anything that would date the figure |
| `annotate` | no | Red boxes and underlines, described above |
| `settle` | no | Milliseconds to wait after the last step, default 400 |
| `caption` | no | Figure caption, copied into `figures.json` |

### Capturing a menu together with the control that opened it

MUI mounts a menu, a popover, or an autocomplete at the end of `<body>` rather
than inside the button that opened it, so no single element contains both. Pass
`element` a list and the clip becomes the union of every box in it:

```yaml
    element:
      - 'table'
      - '.MuiMenu-paper'
```

Prefer this over capturing the whole viewport. A page with three cards on it
leaves two thirds of a 1440x1000 figure empty, which reads as a broken
screenshot rather than a deliberate one. A shorter `viewport` is the other way
to get the same result, and shots sharing a geometry are captured together, so
it costs one extra browser connection no matter how many shots use it.

### Figures that need somebody else to be there

Some of the interface only exists when a second operator is genuinely present.
The clearest case is the chat composer's `@mention` autocomplete: its roster is
this net's check-ins intersected with live WebSocket presence, so in a session
with nobody else signed in the list is empty and the menu never opens. There is
no fixture for this. `with_online` signs the named callsigns in, parks each on
the same route, and holds the connection open for the length of the shot:

```yaml
    with_online: [K1COVE]
```

They load before the shot's own page does, because a page reads the roster once
on mount.

### Placeholders

Routes and selectors can name a seeded record instead of hardcoding an id that
changes every time the database is rebuilt:

- `{{net:active}}`, `{{net:closed}}`, `{{net:scheduled}}` — the seeded nets
- `{{template:weekly}}` — a seeded schedule

## When to re-run it

After any release that changes the check-in table, the net toolbar, the card
buttons, or the dialogs. It is one command, and it is meant to be handed to an
agent in one line.
